# task-5-r1 Rendered Group Flow

This note connects the rendered GUI path to the scoped verification gate. The gate is intentionally service-level for live E2E, but the code path the customer uses in the app is the same group model, coordinator, HTTP service, and backend route surface.

Send prepares the latest epoch key, encrypts the plaintext into a group ciphertext, sends only that ciphertext over `GroupService`, and appends a local display message attributed as `"You"` (`mac-app/Sources/ChatApp/Groups/GroupCoordinator.swift:254`, `mac-app/Sources/ChatApp/Groups/GroupCoordinator.swift:267`, `mac-app/Sources/ChatApp/Groups/GroupCoordinator.swift:273`, `mac-app/Sources/ChatApp/Groups/GroupCoordinator.swift:274`, `mac-app/Sources/ChatApp/Groups/GroupCoordinator.swift:276`, `mac-app/Sources/ChatApp/Groups/GroupCoordinator.swift:279`). Live receive starts an SSE stream with an epoch-change hook, appends live records after decryption, and refreshes detail/keys/list on epoch events (`mac-app/Sources/ChatApp/Groups/GroupCoordinator.swift:381`, `mac-app/Sources/ChatApp/Groups/GroupCoordinator.swift:388`, `mac-app/Sources/ChatApp/Groups/GroupCoordinator.swift:391`, `mac-app/Sources/ChatApp/Groups/GroupCoordinator.swift:393`, `mac-app/Sources/ChatApp/Groups/GroupCoordinator.swift:397`, `mac-app/Sources/ChatApp/Groups/GroupCoordinator.swift:401`, `mac-app/Sources/ChatApp/Groups/GroupCoordinator.swift:414`, `mac-app/Sources/ChatApp/Groups/GroupCoordinator.swift:419`, `mac-app/Sources/ChatApp/Groups/GroupCoordinator.swift:420`, `mac-app/Sources/ChatApp/Groups/GroupCoordinator.swift:421`).

## HTTP Wire: `GroupService.swift`

`GroupService` defines the complete app/backend contract for creating groups, listing/fetching groups, adding members, fetching keys, sending ciphertext, fetching history, and opening the live stream (`mac-app/Sources/ChatApp/Groups/GroupService.swift:3`, `mac-app/Sources/ChatApp/Groups/GroupService.swift:4`, `mac-app/Sources/ChatApp/Groups/GroupService.swift:5`, `mac-app/Sources/ChatApp/Groups/GroupService.swift:6`, `mac-app/Sources/ChatApp/Groups/GroupService.swift:7`, `mac-app/Sources/ChatApp/Groups/GroupService.swift:8`, `mac-app/Sources/ChatApp/Groups/GroupService.swift:9`, `mac-app/Sources/ChatApp/Groups/GroupService.swift:10`, `mac-app/Sources/ChatApp/Groups/GroupService.swift:11`). `HTTPGroupService` sends group creation to `POST /groups`, member add to `POST /groups/:id/members`, keys to `GET /groups/:id/keys`, group messages to `POST /groups/:id/messages`, history to `GET /groups/:id/messages`, and live messages to `GET /groups/:id/stream` (`mac-app/Sources/ChatApp/Groups/GroupService.swift:55`, `mac-app/Sources/ChatApp/Groups/GroupService.swift:76`, `mac-app/Sources/ChatApp/Groups/GroupService.swift:79`, `mac-app/Sources/ChatApp/Groups/GroupService.swift:83`, `mac-app/Sources/ChatApp/Groups/GroupService.swift:87`, `mac-app/Sources/ChatApp/Groups/GroupService.swift:114`, `mac-app/Sources/ChatApp/Groups/GroupService.swift:149`). ## Why The Scoped Gate Still Proves The Customer Flow

The scoped live test uses the real `HTTPGroupService` against a freshly booted backend and a real SQLite DB, but avoids the heavy multi-coordinator SSE test that causes the 125-second resource-exhaustion failure. It creates a named group, distributes wrapped epoch keys, sends an encrypted sentinel, verifies a member decrypts the history and live record, confirms the sentinel is absent from the wire, and adds a late member who has no epoch-0 key and cannot decrypt the epoch-0 ciphertext (`mac-app/Tests/ChatAppTests/LiveGroupE2ETests.swift:233`, `mac-app/Tests/ChatAppTests/LiveGroupE2ETests.swift:264`, `mac-app/Tests/ChatAppTests/LiveGroupE2ETests.swift:275`, `mac-app/Tests/ChatAppTests/LiveGroupE2ETests.swift:305`, `mac-app/Tests/ChatAppTests/LiveGroupE2ETests.swift:327`, `mac-app/Tests/ChatAppTests/LiveGroupE2ETests.swift:333`, `mac-app/Tests/ChatAppTests/LiveGroupE2ETests.swift:380`, `mac-app/Tests/ChatAppTests/LiveGroupE2ETests.swift:388`).

The verification script then independently inspects the live artifacts and DB: it checks the run executed exactly one scoped live test, verifies artifact presence, compares captured wire ciphertext to stored DB ciphertext, checks history and raw DB bytes for sentinel absence, proves the late member has zero epoch-0 key rows and `joined_epoch == 1`, and checks schema column names for ciphertext/wrapped-key-only storage (`.agentloop/state/tasks/task-5-r1/verify.sh:181`, `.agentloop/state/tasks/task-5-r1/verify.sh:191`, `.agentloop/state/tasks/task-5-r1/verify.sh:209`, `.agentloop/state/tasks/task-5-r1/verify.sh:226`, `.agentloop/state/tasks/task-5-r1/verify.sh:233`, `.agentloop/state/tasks/task-5-r1/verify.sh:242`, `.agentloop/state/tasks/task-5-r1/verify.sh:253`, `.agentloop/state/tasks/task-5-r1/verify.sh:258`, `.agentloop/state/tasks/task-5-r1/verify.sh:288`). The captured gate output shows this single live test passed and the gate ended green (`.agentloop/state/tasks/task-5-r1/scoped_gate_run.log:290`, `.agentloop/state/tasks/task-5-r1/scoped_gate_run.log:298`, `.agentloop/state/tasks/task-5-r1/scoped_gate_run.log:301`, `.agentloop/state/tasks/task-5-r1/scoped_gate_run.log:310`).

That split is intentional: the 20 `GroupCoordinatorTests` prove the rendered multi-member coordinator path, including create/open/add/send, username and `"You"` attribution, live receive, rekey, and epoch self-heal. The scoped live test proves the same cryptographic invariants over the actual HTTP wire and database without running the excluded long-lived coordinator E2E subscriptions.
